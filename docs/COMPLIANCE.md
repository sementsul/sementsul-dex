# Комплаенс: геоблокировка и санкционные адреса

Что сделано, чего сознательно не сделано, и где границы этой защиты.

Читать целиком перед тем, как менять списки стран или правила: несколько
решений выглядят как недосмотр, но приняты осознанно.

---

## Коротко

| Механизм | Где | Что делает |
|---|---|---|
| Геоблокировка по стране | `functions/api/geo.js` + `src/lib/compliance.js` | закрывает интерфейс для Ирана, КНДР, Сирии, Кубы |
| Геоблокировка по региону | там же | Крым, Донецкая, Луганская, Запорожская, Херсонская области |
| Санкционный список адресов | `public/sanctions/ofac-addresses.json` | 127 адресов из OFAC SDN |
| Принудительный гейт | `src/lib/wallet.js` | блокирует **любую** транзакцию, а не только кнопку |

Проверки: `npm test` — наборы «комплаенс» (61 + 24 проверки) и отдельно
`test-compliance-docs.mjs`, который не даёт документации разойтись с кодом.

## Чего здесь НЕТ

Это важно понять до того, как обещать кому-то «AML как у Uniswap».

**Нет графового анализа транзакций.** TRM Labs и Chainalysis, которые
используют Uniswap Labs и PancakeSwap, — платные сервисы. Они смотрят не
только на сам адрес, но и на то, с чем он связан: перевод на один хоп от
миксера, получение средств со взломанного протокола, принадлежность к
кластеру биржи под санкциями. Воспроизвести это самостоятельно нельзя:
нужны размеченные данные, которых у нас нет.

**Нет проверки истории кошелька.** Список OFAC — это «кого уже поймали и
вписали в документ». Адрес, который завтра примет деньги от Lazarus, сегодня
в списке ещё не появится. Обещать «мы проверим, что кошелёк чистый» было бы
ложью.

**Нет блокировки на уровне смарт-контрактов.** Контракты неизменяемы и не
знают, кто их вызывает. Любой, у кого есть адрес пула, может вызвать его
через Etherscan или свой скрипт, минуя этот сайт.

Поэтому в интерфейсе написано «адрес внесён в санкционный список OFAC», а не
«кошелёк высокорисковый». Второе было бы неправдой.

## Что именно блокируется

### Страны

Юрисдикции под **всеобъемлющими** санкциями США (comprehensive sanctions
OFAC), где запрещены операции практически со всей территорией:

- Иран (`IR`)
- КНДР (`KP`)
- Сирия (`SY`)
- Куба (`CU`)

### Регионы Украины

Крым, Донецкая, Луганская, Запорожская и Херсонская области.

Техническая сложность: Cloudflare отдаёт для них `country = 'UA'`, то есть
ту же страну, что и для остальной Украины. Отличить можно только по полю
`region`, а оно заполняется не для всех IP и содержит название области
текстом. Сопоставление идёт по подстрокам (`crimea`, `donetsk`, `luhansk`,
`zaporizh`, `kherson`).

**Это эвристика, и она может ошибаться в обе стороны:**

- житель подконтрольной Украине части Запорожской области увидит блокировку;
- если Cloudflare не заполнит `region`, проверка не сработает.

Поэтому при срабатывании по региону показывается отдельный текст с
предложением сообщить об ошибке, а не глухой отказ.

### Почему Россия и Беларусь НЕ заблокированы

Это не недосмотр. Россия находится под **секторальными** санкциями: они
запрещают конкретные операции (долг, энергетика, технологии, отдельные
лица), но не операции со всей страной целиком. Беларусь — аналогично.

Блокировать всю Россию на сайте — это уже не исполнение санкций, а
самодеятельность: она задела бы миллионы людей, против которых ничего не
выпущено, и юридически ничем не обоснована. Если политика изменится, правка
делается в одном месте — `BLOCKED_COUNTRIES` в `src/lib/compliance.js`, —
но менять её нужно осознанно, а не «на всякий случай».

## Как работает геоблокировка

```
браузер → GET /api/geo → Cloudflare Pages Function
                          читает request.cf.country / region
                          (IP уже известен границе)
         ← { country, region, regionCode }
       → evaluateGeo() → если страна или регион под санкциями
       → <BlockedScreen> вместо всего интерфейса
```

**Почему на сервере, а не в браузере.** IP клиента знает только граница.
Спрашивать сторонний гео-сервис из браузера — значит отдавать IP
пользователя третьей стороне без нужды. `request.cf` уже заполнен
Cloudflare, наружу ничего не уходит.

**Почему отдельный эндпоинт, а не middleware.** Пользователь видит внятное
объяснение, а не голый `451`. Страницу можно открыть с другого адреса и
понять причину. Если понадобится жёсткая блокировка на границе —
`functions/_middleware.js` с проверкой `request.cf.country` и возвратом `451`;
шаблон описан ниже.

**Ответ не кэшируется.** `cache-control: no-store, private` и
`vary: CF-Connecting-IP`. Без этого общий кэш CDN раздал бы страну одного
пользователя всем остальным.

**Провал определения не блокирует сайт.** Если `/api/geo` недоступен
(локальная разработка, сбой), `geo` остаётся `null`, и `evaluateGeo(null)`
возвращает `blocked: false`. Иначе одна ошибка нашего же API закрыла бы
биржу целиком.

### Ограничение `_routes.json`

`public/_routes.json` содержит `{"include": ["/api/*"], "exclude": []}`.

Это не украшение. Как только в проекте появляется папка `functions/`,
Cloudflare по умолчанию начинает вызывать Function на **каждый** запрос, и
бесплатный лимит Pages Functions (100 000 вызовов в сутки) сгорает на
раздаче статики. `_routes.json` ограничивает вызовы только путями `/api/*`.

Важная деталь: `exclude` имеет приоритет над `include`. Написать
`"exclude": ["/*"]` вместе с `"include": ["/api/*"]` — значит отключить
функцию полностью, включая `/api/geo`. Такой вариант я едва не оставил в
коде; тест `test-compliance-integration.mjs` проверяет, что этого не
случилось.

## Санкционный список

### Источник

Официальный `SDN.XML` с сервиса Минфина США:

```
https://sanctionslistservice.ofac.treas.gov/api/PublicationPreview/exports/SDN.XML
```

Это первоисточник. TRM и Chainalysis строят свои продукты поверх него.

Сборка:

```bash
node scripts/build-sanctions-list.mjs
```

Скрипт скачивает XML (28 МБ, ~13 с), вытаскивает все записи вида
`Digital Currency Address`, оставляет адреса формата `0x…` и пишет
`public/sanctions/ofac-addresses.json`.

Результат: **127 уникальных адресов** (`ETH` 123, `USDT` 8, `USDC` 2,
`BSC` 1, `ARB` 1, `ETC` 1).

Фильтр идёт по формату, а не по сети: любой `0x`-адрес EVM-совместим, и
OFAC может пометить его как `ETH`, хотя тот же адрес используется в BSC.
Поэтому в список попадают все `0x`, а сеть сохраняется как справка.

### Почему в списке нет Tornado Cash

OFAC внёс адреса Tornado Cash в августе 2022, но в **марте 2025 исключил**
их после решения суда по делу Van Loon v. Department of the Treasury.
Поэтому их отсутствие — правильное состояние, а не сломанный разбор.

Если однажды понадобится контрольный адрес для проверки парсера, брать
Lazarus Group (`0x098b716b…`), а не Tornado: список живой и меняется.

### Защита от молчаливой поломки

Скрипт падает, если:

- найдено меньше 50 адресов — вероятно, изменился формат XML;
- ни один контрольный адрес Lazarus не найден — разбор сломан.

Лучше упасть, чем выложить сайт с пустым списком и считать, что всё цело.

### Ручные дополнения

Если нужен источник без машиночитаемой выгрузки (например,
консолидированный список ЕС), адреса кладутся в
`data/sanctions-extra.json`:

```json
{
  "addresses": {
    "0x...": { "names": ["..."], "programs": ["EU-..."], "networks": ["ETH"] }
  }
}
```

Файл необязательный. Сейчас его нет — работает только OFAC.

### Обновление

Список статический, лежит в репозитории. Обновлять вручную:

```bash
node scripts/build-sanctions-list.mjs
npm test            # проверит формат и контрольные адреса
npm run build
npx wrangler pages deploy dist --project-name=sementsul-dex
```

Автоматизации через cron нет сознательно: правка списка меняет то, кому
закрыт доступ, и это должно быть видно в истории git как отдельный коммит.

## Гейт транзакций

Ключевая часть. Все операции записи в приложении — обмен, добавление и
снятие ликвидности, создание пула — идут через одну функцию
`sendTransaction` в `src/lib/wallet.js`. Проверка стоит в ней:

```js
let complianceGate = null
export function setComplianceGate(fn) { complianceGate = ... }

export async function sendTransaction({ to, data, value, gasLimit }) {
  if (complianceGate) complianceGate()   // бросает Error, если запрещено
  ...
}
```

`useCompliance` регистрирует гейт через `useWallet`, поэтому блокировка
действует на **любую** транзакцию, а не только на ту кнопку, обработчик
которой её проверяет.

Тест `test-compliance-integration.mjs` фиксирует главное: при активном гейте
кошелёк **не вызывается вообще** (`ethCalls === 0`). То есть блокировка
срабатывает до `eth_estimateGas` и до `eth_sendTransaction`, а не после
подписи.

### Почему это барьер, а не граница безопасности

Фронтенд работает в браузере пользователя. Его можно обойти: отключить JS,
подменить `fetch`, переписать `window.ethereum`, убрать гейт через devtools.
Это нормально и так же у всех: Uniswap Labs и PancakeSwap блокируют
интерфейс, а не протокол.

Настоящая граница — смарт-контракты, но они неизменяемы и не знают, кто их
вызывает. Юридически значимый контроль для некастодиального протокола
возможен только на уровне интерфейса.

### Чего гейт не делает

Не блокирует **чтение**. Заблокированный пользователь видит балансы, пулы,
курсы и базу знаний — просто не может совершать операции. Это осознанно:
скрывать информацию бессмысленно, она и так в блокчейне.

## Поведение при сбоях

| Сбой | Поведение | Почему |
|---|---|---|
| `/api/geo` недоступен | сайт работает, гео-проверки нет | сбой нашего API не должен закрывать биржу |
| `/sanctions/ofac-addresses.json` не загрузился | сайт работает, показывается плашка «список не загрузился» | честно сообщаем, что проверка не выполнялась |
| адрес не в списке | операции разрешены | отсутствие в списке не означает «чистый», но и блокировать не за что |
| `checkAddress` ещё выполняется | операции **разрешены** | иначе кнопка мигала бы при каждом подключении |

Последний пункт — компромисс. Адрес попадает в список OFAC не внезапно, и
доли секунды до ответа ничего не решают, а мигающий интерфейс раздражает
каждого.

## Ужесточение: блокировка на границе

Если понадобится закрыть сайт полностью, а не только операции, — создать
`functions/_middleware.js`:

```js
const BLOCKED = new Set(['IR', 'KP', 'SY', 'CU'])

export async function onRequest({ request, next }) {
  const country = request.cf?.country
  if (country && BLOCKED.has(country)) {
    return new Response('Unavailable in your jurisdiction', {
      status: 451, // Unavailable For Legal Reasons
      headers: { 'content-type': 'text/plain; charset=utf-8' },
    })
  }
  return next()
}
```

`451` — корректный код для «недоступно по юридическим причинам», в отличие
от `403`.

Но у этого варианта есть цена: он срабатывает и на `/api/geo`, то есть
пользователь не увидит объяснения, а поисковые роботы и архивы получат
отказ. Поэтому сейчас выбран мягкий вариант.

## Юридическая оговорка

Этот документ описывает техническую реализацию, а не юридическую позицию.
Sementsul DEX — некастодиальный интерфейс к неизменяемым смарт-контрактам в
BNB Chain:

- контракты остаются общедоступными и не контролируются этим сайтом;
- ограничение относится к использованию интерфейса;
- проверка по списку OFAC снижает риск, но не заменяет комплаенс-программу.

Решение о том, какие юрисдикции блокировать и какие источники использовать,
принимает оператор сервиса.
