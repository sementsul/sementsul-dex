# Как пушить, чтобы GitHub Actions не отключился

## Проблема

GitHub отключает workflow по расписанию (cron), если в репозитории нет
**активности от владельца** 60 дней. `verify.yml` ходит по cron каждый час,
и без пушей он замолчит примерно через два месяца после последней активности.

Тонкость: засчитывается не любой пуш. Пуш, сделанный через встроенный
`GITHUB_TOKEN` (например, из самого workflow или из CI), **не считается** —
GitHub не видит в нём действия человека. Нужен пуш, авторизованный личным
токеном владельца.

## Что настроено

В Windows Credential Manager для `github.com` записан личный токен
(`ghp_…`), а не OAuth-токен внутреннего хранилища (`gho_…`). Именно `ghp_`
считается личным действием.

Проверить, какой токен сейчас используется:

```powershell
"protocol=https`nhost=github.com`n`n" | git credential fill
```

В выводе `password=` — токен. Префикс `ghp_` означает личный токен, `gho_` —
OAuth. Нужен `ghp_`.

Заменить токен:

```powershell
$new = 'ghp_...'
"protocol=https`nhost=github.com`n`n" | git credential reject
"protocol=https`nhost=github.com`nusername=sementsul`npassword=$new`n`n" | git credential approve
```

## Второе, что было исправлено: email коммитов

GitHub привязывает коммит к аккаунту по email автора. Если email в коммите не
совпадает ни с одним подтверждённым адресом аккаунта, коммит остаётся
«висящим»: в интерфейсе он есть, но к профилю не относится.

Было:

```
sementsul <sementsul@gmail.com>   <- такого адреса в аккаунте нет
```

Стало:

```
sementsul <45505876+sementsul@users.noreply.github.com>
```

Этот адрес GitHub выдаёт каждому аккаунту; он подтверждён по определению и,
в отличие от настоящей почты, не раскрывает её в публичной истории.

Настроено локально для репозитория:

```bash
git config user.email "45505876+sementsul@users.noreply.github.com"
```

## Как поддерживать активность

Достаточно одного осмысленного пуша раз в пару месяцев — например, обновление
документации после очередного изменения. Специально «пушить ради галочки»
не нужно и вредно: пустые коммиты засоряют историю.

Проверить, что workflow ещё активен:

```powershell
curl -H "Authorization: Bearer $env:GH_TOKEN" `
  https://api.github.com/repos/sementsul/sementsul-dex/actions/workflows
```

Поле `"state": "active"` означает, что расписание работает. Если там
`"state": "disabled_inactivity"`, workflow отключён по неактивности — его
включают вручную во вкладке Actions кнопкой «Enable workflow».

## Про сам токен

Токен — это пароль. Он не записан в репозиторий и не должен там оказаться:
`.env` в `.gitignore`, в коде его нет. Если токен попал в чужую переписку или
скриншот, его отзывают на github.com/settings/tokens и выпускают новый.

Права токена сейчас широкие (`repo`, `workflow`, `admin:org` и другие).
Для пуша в один репозиторий достаточно `repo`. Более узкий scope уменьшает
ущерб, если токен утечёт.
