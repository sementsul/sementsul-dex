## Пункт 1. Свой V3-роутер

**Файл:** `contracts/SementsulV3Router.sol` (6 808 байт создания, 6 396 развёрнуто)

Что умеет:

| Функция | Назначение |
|---|---|
| `exactInputSingle` | точный вход, один пул |
| `exactInput` | точный вход, маршрут из нескольких пулов |
| `exactOutputSingle` | точный выход, один пул |
| `exactOutput` | точный выход, маршрут (обратный порядок) |
| `multicall` | несколько вызовов в одной транзакции |
| `unwrapWBNB` / `wrapBNB` / `refundBNB` | работа с BNB |

Формат маршрута — `token(20) + fee(3) + token(20) + ...`, как в Uniswap V3,
поэтому маршрут, собранный их инструментами, подходит без переделки.

**Тесты:** 11, все проходят (`test/V3Router.t.sol`).

### Что нашлось при написании

**Ошибка в пуле, жившая незамеченной.** При точном выходе суммы возвращались
перепутанными: формула в `swap()` верна только для точного входа. Никто не
замечал, потому что точный выход до появления роутера никто не вызывал —
фронтенд и скрипты работают только с точным входом. Поймал тест
`test_exactOutputSingle`.

Проверка после исправления:
```
exact output: spent tokenIn:  5 002 751 263 125 937 689
exact output: received tokenOut: 5 000 000 000 000 000 000
```
Отдал 5.0028 за ровно 5.0 при комиссии 0.05% — арифметика верна.

## Пункт 2. Callback-оплата

**Файл:** `contracts/SementsulV3.sol`

Пул реализует `uniswapV3SwapCallback` **и** `pancakeV3SwapCallback` — часть
инструментов BSC ищет именно второй селектор.

Ветка оплаты выбирается по наличию кода у `msg.sender`, а **не** по флагу в
calldata: флаг позволил бы контракту притвориться кошельком и уйти от оплаты,
получив выход.

| Кто вызывает | Как платит |
|---|---|
| Кошелёк (кода нет) | `transferFrom` — привычный путь, всё работает как раньше |
| Контракт (роутер, агрегатор) | пул отдаёт выход → callback → сверка роста баланса |

Проверка оплаты одна, но настоящая: после callback'а баланс пула должен
вырасти хотя бы на сумму долга. Без неё контракт ответил бы на callback
пустым телом и получил выход бесплатно.

**Тест, доказывающий необходимость:** при первом прогоне `SharedRouter` без
callback упал с `unrecognized function selector 0xfa461e33`. Ровно так ведёт
себя любой существующий роутер агрегатора на нашем пуле до этой правки.

## Пункт 3. Пропорциональный штраф за разворот

**Настройка:** `setReversalPenaltyK(fee, k)`, `setMaxReversalPenalty(max)`

Ставка штрафа = `k × сдвиг цены`, потолок по умолчанию 10%.

Почему не фиксированный процент: прибыль бота растёт как **квадрат** сдвига
(он сам его создаёт), фиксированный штраф — **линейно**. При пуле $100k и
штрафе 1% бот на сдвиге 2% зарабатывает $39 и платит $20 — остаётся в плюсе.
Пропорциональный штраф растёт с той же скоростью, и бот в минусе при любом
размере.

| Сдвиг | Ставка | Бот заработал | Штраф | Итог |
|---|---|---|---|---|
| 0.5% | 0.50% | 2.45 | 2.51 | −0.06 |
| 1.0% | 1.00% | 9.80 | 10.10 | −0.30 |
| 5.0% | 5.00% | 245.00 | 262.50 | −17.50 |
| 10.0% | 10.00% | 980.00 | 1100.00 | −120.00 |

**По умолчанию выключено** (`k = 0`). Причина в пункте 5.

## Пункт 4. Учёт маршрута

**Функция:** `SementsulV3Factory.noteSwap(pool)`

Если в блоке уже торговал **другой** пул нашей фабрики, разворот не
наказывается: это может быть маршрут через несколько пулов (арбитраж или
агрегатор). Вызывать может только пул фабрики — иначе любой контракт
подделал бы «маршрут» одной транзакцией.

Правило намеренно **грубое**, и это выбор в пользу безопасности: два
независимых пользователя в разных пулах одного блока тоже дадут «маршрут», и
штраф не сработает. Лучше пропустить бота, чем взять 10% с того, кто просто
торговал.

**Результат в тестах:**
```
multi-hop A->B->C:            NOT penalized (different pools)
triangular arb, two pools:    NOT penalized (route rule protects it)
triangular arb, same pool:    PENALIZED (unfair, but rare at scale)
```

## Пункт 5. Замер ложных срабатываний

**Файл:** `test/FalsePositive.t.sol`, 8 тестов

Прогнаны реалистичные сценарии блока:

| Сценарий | Легальный? | Наказан? |
|---|---|---|
| Простой односторонний обмен | да | нет |
| Мульти-хоп A→B→C | да | нет |
| Треугольный арбитраж через 2 пула | да | нет |
| Два разных пользователя, разные направления | да | **да** |
| Пользователь передумал и развернулся | да | **да** |
| Треугольный арбитраж через 1 пул | да | **да** |
| Настоящий сэндвич | нет | да |

**Итог: 3 из 6 легальных сценариев наказываются.**

Это и есть причина, по которой штраф выключен по умолчанию. Механизм не
различает участников — он различает только последовательность направлений в
блоке. Всё, что похоже на разворот, попадает под него, включая невиновных.

Плюс главное ограничение из прошлого разбора, которое никуда не делось:
**бот обходит штраф, разнеся плечи по разным блокам.** На BSC блок 0.448 с,
цена обхода — меньше половины секунды.

## Что ещё нашлось по дороге

### Фабрика V3 вшивает в себя код пула

Развёрнутый код фабрики — **23 994 байта** при лимите EIP-170 в 24 576.
Запас **582 байта** (2.4%). Любая следующая правка пула увеличивает и
фабрику, потому что `creationCode` пула лежит внутри неё.

Компилятор теперь предупреждает об этом заранее.

### Ошибка в проверке размера

`compile.mjs` сравнивал с лимитом EIP-170 **код создания**, а не развёрнутый.
Из-за этого фабрика «не влезала» в лимит, хотя её развёрнутый код меньше.
Исправлено; проверка теперь смотрит на `deployedBytecode`.

### Неверный адрес роутера во фронтенде

`src/lib/contracts.js` указывал `V3_ROUTER` на `deployments.router` — роутер
**V2**, у которого нет ни одной V3-функции. Фронтенд собирал calldata
`exactInputSingle` и отправлял контракту, который такого метода не знает.
Теперь есть `deployments.v3Router`.

## Что осталось за границей сделанного

1. **Штраф выключен по умолчанию.** Включать только после замера доли ложных
   срабатываний на реальном трафике тестовой сети. Пункт 5 показывает, что
   эта доля не мала.
2. **Обход через блоки не закрыт** и в контракте закрыт быть не может —
   только приватным RPC и порядком транзакций.
3. **Квотера V3 нет.** Котировки идут оценкой по `slot0`, поэтому для
   многошаговых маршрутов они приблизительные.
4. **Деплой не выполнен.** Нужны `DEPLOYER_KEY` и ~0.01 BNB.
