# Передеплой или добавление? Разбор по каждому пункту

Вопрос: «это не передеплой уже имеющихся контрактов?»
Короткий ответ: **нет, это добавление.** Ниже — почему, с проверками на цепи.

Проверено на блоке ~136 046 400. Скрипт: `scripts/what-needs-redeploy.mjs`.

---

## Главное различие: что хранит деньги

Ключ ко всему ответу. В системе три роли, и только одна из них держит
средства:

| контракт | что хранит | можно ли менять |
|---|---|---|
| **Пул** `0x37c7…0278` | **деньги** (USDT + WBNB), позиции LP | нет, и не нужно |
| **Фабрика** `0xc0b5…4dd9` | реестр пулов, настройки тиров | нет, и не нужно |
| **Роутер** `0xf98b…fdd1` | **ничего** — только маршрутизирует | да, безопасно |
| **Quoter** | не существует | создать |

Роутер и quoter **не хранят состояние**. Они не могут распоряжаться
ликвидностью пула: у пула нет функции «админ выводит», `onlyAdmin` есть
только у трёх сеттеров фабрики (`setJitDelayBlocks`,
`setReversalPenaltyK`, `setMaxReversalPenalty`), и ни один из них не трогает
деньги.

Значит новый роутер — это **новый инструмент доступа к тому же пулу**, а не
замена пула.

---

## Проверка: новый роутер увидит старый пул

Это не предположение. Проверил на цепи:

```
роутер → FACTORY  = 0xc0B597Be…24dD9   (immutable, задан в конструкторе)
роутер → WBNB     = 0xbb4CdB9C…bc095c  (immutable)
пул    → factory  = 0xc0B597Be…24dD9   ← ТА ЖЕ фабрика
фабрика.getPool(USDT, WBNB, 500) = 0x37c7702B…780278  ← тот же пул
фабрика.isPool(наш пул) = true
```

Смотрите на строку 87 исходника роутера:

```solidity
constructor(address _factory, address _wbnb) {
    require(_factory != address(0), 'SementsulRouter: FACTORY_ZERO');
    FACTORY = _factory;
```

`FACTORY` — `immutable`. Это значит: **новый роутер деплоится с тем же
адресом фабрики в конструкторе и автоматически работает с существующими
пулами.** Ничего переносить не надо, ликвидность остаётся на месте.

Роутер находит пул через фабрику (`строка 362`):
```solidity
pool = ISementsulV3Factory(FACTORY).getPool(token0, token1, fee);
require(ISementsulV3Factory(FACTORY).isPool(pool), 'SementsulRouter: NOT_OUR_POOL');
```

То есть роутер вообще не хранит адреса пулов — он их спрашивает у фабрики
каждый раз. Захватит новые пулы автоматически.

## Что именно делаем по каждому пункту

### 1. Quoter — чистый новый контракт

Ранее **не существовал**. В байткоде роутера, пула и фабрики селектор
`quoteExactInput` отсутствует — проверил.

Это не «передеплой», а создание того, чего не было. Риска ноль: контракт
только читает состояние пула и считает по формуле. Нет функций, меняющих
что-либо. Даже если в нём будет ошибка — пострадает только расчёт, деньги
останутся в пуле.

Что нужно:
```
deploy SementsulQuoter(factory, wbnb)
```
Один конструктор, два immutable-аргумента.

### 2. Роутер со стандартным ISwapRouter — новый контракт, старый остаётся

Здесь важно понять: **старый роутер не удаляется и не ломается.** Контракты
на цепи не «перезаписываются». Появится второй роутер с тем же `FACTORY`,
но с другими селекторами.

Что это меняет на практике:

| | старый `0xf98b…fdd1` | новый |
|---|---|---|
| `exactInputSingle` | `0xea7ec9c4` (4 поля + deadline) | `0x414bf389` (8 полей) |
| кто использует | ваш фронтенд | агрегаторы |
| работает с пулом | да | да, тот же пул |

**Важный побочный эффект: approve придётся выдать заново.**

Проверил, как фронтенд даёт разрешение (`src/onchain/swap.js`, строка 168):
```js
buildApprove(token, spender, amount)
```
`spender` — это адрес роутера. При смене роутера старые approve
**не подхватятся**: allowance привязан к паре (токен, spender).

Для вас как для владельца это значит: при переходе на новый роутер
пользователям (и боту) нужно будет один раз заново одобрить токены. Это
нормально и ожидаемо, но об этом надо предупредить заранее — иначе люди
увидят «не удалось списать токен».

Переключение делается в одном месте. Адрес берётся из
`src/contracts/deployments.js`, строка 28:
```js
"v3Router": "0xf98b7f4effb34dae1f785010ecf71ff796e7fdd1",
```
Меняете на новый адрес → `npm run build` → деплой на Pages. Больше нигде
адрес роутера не зашит (в `app.js` — ноль вхождений, всё через `config.js`).

### 3. Адаптер «Uniswap-вид» — новый контракт, польза ограничена

Ранее не существовал. Обёртка только для чтения: отдаёт `slot0` из 7 полей
(добивая нулями) и `ticks` из 8.

Здесь повторю предупреждение, потому что оно важнее технической части:
`observe()` адаптер честно ответить не сможет. Оракула в пуле нет —
селекторы `observe` и `increaseObservationCardinalityNext` отсутствуют в
байткоде, и никакая обёртка их не создаст: пул не хранит историю цены,
взять её неоткуда.

Подделывать TWAP нельзя. Если адаптер вернёт нули или «текущую цену как
среднюю», кто-то построит на этом стратегию и потеряет деньги — а виноват
будет тот, кто задеплоил. Правильно — отдавать реверт с внятной причиной.
Но тогда адаптер бесполезен ровно для тех, кому нужен TWAP, и помогает
только тем, кто читает `slot0`/`ticks`.

Вывод: делать можно, но это косметика, а не решение.

### 4. Оракул TWAP — не делать

Технически это отдельный контракт с обновлятором. Но:
- нужен кто-то, кто пишет цену каждые N блоков и тратит газ постоянно;
- кто пишет — тот и определяет цену, то есть требует доверия;
- без стимула обновлять данные устаревают, и оракул начинает врать.

На пуле в $639 с доходом $1.25/сутки это не окупается и создаёт риск,
которого сейчас нет.

## Чего НЕ придётся делать

Перечислю явно, потому что страх «передеплоя» обычно про это:

- **Не надо пересоздавать пул.** Ликвидность `4476431973545015091567`
  остаётся на месте.
- **Не надо выводить и заново вносить ликвидность.** Позиция бота и ваша
  позиция не затрагиваются.
- **Не надо передеплоивать фабрику.** Реестр пулов остаётся.
- **Не надо менять настройки тиров.** `reversalPenaltyK(500) = 0` и прочее
  остаются.
- **Не теряются адреса.** Все текущие ссылки, чарты DexScreener, on-chain
  зеркало — продолжают работать.
- **Старый роутер продолжает работать.** Его можно не трогать вообще.

---

## Что действительно передеплоивается

Только то, что хранит логику, которую надо изменить:

```
┌ роутер    НОВЫЙ контракт  (старый остаётся жить)
├ quoter    НОВЫЙ, ранее не было
├ адаптер   НОВЫЙ, ранее не было
├ пул       НЕ ТРОГАЕМ  ← там деньги
└ фабрика   НЕ ТРОГАЕМ  ← там реестр
```

Формально: три новых контракта, ноль замен. Ни один существующий адрес не
меняет поведение.

## Порядок работ, если решите делать

**Шаг 1. Quoter.** Самый дешёвый и безопасный. Ничего не ломает, даёт
агрегаторам возможность считать выход.

**Шаг 2. Проверить, нужен ли роутер вообще.** Прежде чем деплоить, стоит
ответить: есть ли хоть один агрегатор, который согласится нас добавить?
Если нет — роутер пролежит без дела. Это не технический вопрос, а
переговорный, и он должен идти первым.

**Шаг 3. Роутер.** Если ответ на шаг 2 положительный.

**Шаг 4. Адаптер** — по желанию, косметика.

---

## Честная оценка выгоды

Ни один из этих трёх контрактов **не приносит денег сам по себе**. Они
снимают технические препятствия. Придут ли через них деньги — зависит от
того, попадём ли мы в списки фабрик агрегаторов, а это переговоры и
репутация, не код.

Текущие числа, чтобы не было иллюзий: $2 500 объёма в сутки, $1.25
комиссий в сутки. Даже рост объёма в 10 раз даст $12.50 в сутки.

Расходы на деплой: газ копеечный (BSC, 0.05 gwei — три контракта обойдутся
меньше $1). Расходы на работу: реальные — написание, тесты, проверка,
обновление фронтенда, предупреждение пользователей про повторный approve.
